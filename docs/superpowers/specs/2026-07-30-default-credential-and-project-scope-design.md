# 日报默认凭据与项目范围设计

## 目标

减少日报发送、查询、领取和回执过程中的重复确认。凭据在运行端完成一次配置后自动使用；首次生成本周工作总结时确认项目范围并保存，后续自动复用。

## 行为

### 凭据

- 首次使用或对应角色 Key 未配置时，询问用户提供完整 Key。
- 配置文件或环境变量中已有当前命令所需的 Producer Key 或 Consumer Key 时，直接读取并使用，不再要求逐次授权。
- Key 无效、过期或角色不匹配时停止操作并请用户更新对应角色 Key。
- 始终禁止输出、记录或写入 Git 的 Key、租约令牌和公司系统凭据。
- 发送端与获取端仍可分开部署，各运行端只需要保存本角色 Key。

### 项目范围

- 配置中没有 `weekly_summary_scope` 时，首次生成周报询问使用本周全部项目还是指定项目，并将选择保存到同一配置文件。
- 选择全部项目时保存 `scope.mode=all`；选择指定项目时保存 `scope.mode=whitelist` 和项目名称或路径。
- 后续生成周报复用已保存范围，不再询问目录；用户当前请求主动指定项目时只覆盖本次，不改变保存的范围。
- 当前工具无法提供项目或任务数据时，说明缺失来源并请求补充，不猜测内容。
- `fetch`、`complete`、`fail`、`get`、`list`、`append` 和 `modify` 不需要项目任务数据，执行这些命令时不得询问同步目录或项目范围。

## 修改范围

- 更新 `SKILL.md` 中的凭据确认、首次项目范围确认、发送、查询、修改、获取和错误处理说明。
- 更新 `scripts/test_skill_locale.py`，以静态约束自动读取凭据、首次范围确认、范围持久化以及领取流程不询问项目范围。
- 不修改 Rust 服务、HTTP 契约、Python 客户端配置格式或租约状态机。

## 验证

- 先修改静态测试并确认旧 Skill 文案无法满足新约束。
- 更新 Skill 文档后运行完整 Python 测试、Skill validator 和 `git diff --check`。
- 提交并推送后核对本地与远端 `master` 提交一致。
